# Installation and configuration reference

The root [README](../README.md) gives exact Windows PowerShell and macOS/Linux
installation/startup commands. The Python service and terminal client need Python
3.12+; Node.js is needed only for the optional dashboard. Install locked backend
dependencies from `backend/requirements.lock.txt` and dashboard dependencies with
`npm ci`. Recreate the virtual environment for each operating system.

From the checkout root, `python scripts/bootstrap.py` creates a private `.env`
with a random owner password and mock mode. Use your virtual environment's Python.
Existing `.env` files are preserved. They may retain a previous username: read the
file privately and supply that username with `python -m app.cli --username NAME`.
The CLI prompts for a password and does not read server secrets automatically.

Server settings are loaded from the root `.env` independently of its working
directory. Process environment values take precedence. Restart the service after
changing server settings. Do not place secrets in command arguments, source,
client-side environment variables, or logs.

| Setting | Purpose/default |
| --- | --- |
| `FRED_OWNER_USERNAME` | Owner login identifier; `owner` for a new configuration |
| `FRED_OWNER_NAME` | Configurable displayed owner name; `Owner` |
| `FRED_OWNER_PASSWORD` | Required unique 12–500 character password; generated by bootstrap |
| `FRED_AI_PROVIDER` | `mock` by default; `openai` explicitly enables external inference |
| `OPENAI_API_KEY` | Server-only credential required for `openai` |
| `OPENAI_MODEL` | Initial model default; persisted owner model preference takes precedence |
| `FRED_PERSONALITY_INSTRUCTION` | Provider-independent bounded style guidance; never changes permissions |
| `DATABASE_URL` | Omit for `<checkout>/data/fred.db` SQLite storage |
| `FRED_ALLOWED_ORIGINS` | JSON list of exact browser origins; localhost/127.0.0.1 port 5173 by default |
| `FRED_COOKIE_SECURE` | `false` for loopback HTTP; `true` with a deliberate HTTPS gateway |
| `FRED_SESSION_TTL_HOURS` | Session lifetime; default 12 hours |
| `FRED_API_RATE_LIMIT` | API requests per address/minute; default 120 |
| `FRED_CHAT_RATE_LIMIT` | Chat requests per owner/minute; default 20 |
| `FRED_LOGIN_RATE_LIMIT` | Login attempts per address/minute; default 10 |
| `FRED_OPENAI_TIMEOUT` | Per-attempt provider timeout; default 45 seconds; SDK retries can extend total time |
| `FRED_MEMORY_ENABLED` | `true`; controls chat retrieval; inspection/edit/delete/export remain available |
| `FRED_VOICE_ENABLED` | `false`; enabling it fails startup until implementation exists |
| `FRED_SMART_HOME_ENABLED` | `false`; no live device adapter is installed |
| `FRED_REMOTE_CONTROL_ENABLED` | `false`; no command-execution peer exists |
| `FRED_AUTOMATIONS_ENABLED` | `false`; no routine scheduler exists |
| `FRED_VOICE` | JSON future audio device IDs, wake phrase, timeouts, and echo-cancellation requirements |
| `FRED_ROOMS`, `FRED_DEVICES` | JSON arrays of validated future declarations; both empty by default |

See [.env.example](../.env.example) for exact names and JSON examples. Unknown room
references and duplicate registry IDs are rejected. Registering a device does not
connect it, authorize actions, or enable a feature. Future voice requires local
wake-word processing; cloud ambient-audio monitoring is not an option.

## Provider and saved preferences

Mock mode works without any API key and returns visibly labeled deterministic
responses. OpenAI mode requires a valid project key and model with Chat Completions
support. Connection/authentication/quota/model errors are reported to the client;
no silent provider fallback occurs. Use `/model MODEL` or dashboard Settings to
change an existing saved model, and `/mode MODE` to select communication style.

## Storage and authentication

Keep `.env`, `data/`, databases, and backups out of Git and restricted to the local
owner/service account. POSIX permissions do not establish Windows ACLs; use a
private Windows folder. Changing the configured owner password and restarting
invalidates existing sessions for that owner. This is a single-owner service,
not account provisioning or shared-business authorization.

PostgreSQL can be selected with a SQLAlchemy `postgresql+psycopg://...` URL and a
separately provisioned least-privilege database. It is not validated against a
running PostgreSQL server in this V1. SQLite data is not migrated automatically.
Introduce versioned migrations and verify them against backup copies before
changing persistent production data.

## Network and headless operation

The standard Python entry point binds to loopback; no graphical desktop, browser,
or Node.js process is required for service/terminal use. The API provides
`/api/health` liveness and `/api/ready` database readiness. An authenticated chat
check is still required to verify the selected provider actually responds.

For another device, prepare a trusted HTTPS gateway serving the dashboard and
proxying `/api` and `/api/ws` at the same origin, exact origin configuration,
secure cookies, authentication, and network controls. The supplied app does not
install such a gateway. Never expose Vite or an unauthenticated raw backend port
to the public Internet. The CLI permits plaintext HTTP only for loopback hosts.

See [deployment and recovery](deployment.md) for future Linux systemd supervision,
backup/restore commands, and Windows-to-Linux migration steps.

## Troubleshooting

| Symptom | Next step |
| --- | --- |
| Python or Node command missing | Install Python 3.12; install Node only if using the dashboard; reopen your terminal |
| Owner password missing or rejected at startup | Run bootstrap, then privately inspect `.env`; the placeholder password is invalid |
| Sign-in rejected | Match the username/password in server configuration; restart after edits and respect login rate limits |
| CLI cannot connect | Start the service first and confirm the service URL and `/api/health` response |
| Message times out | Inspect `/history` before retrying; the submitted turn may be saved or still running |
| Feature marked unavailable at startup | Keep the future feature flag false; contracts alone do not enable capability |
| Browser origin/CSRF rejection | Use one documented hostname consistently; sign in again and configure exact trusted origins |
| Data appears absent after moving computers | Restore a verified database backup and reconfigure `DATABASE_URL`; do not copy a venv |
| Backend tests hang only in the managed command sandbox | Use authorized socket-capable execution for the async test client; do not disable assertions |
